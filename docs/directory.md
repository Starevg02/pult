# Каталог AD: изменения из портала

Pult по умолчанию только читает AD. Запись (ADR-0002) включается отдельно и умеет ровно пять операций:
добавить в группу, разблокировать, включить, отключить учётку и сбросить пароль. Произвольного LDAP modify нет.

## Учётка записи

Отдельная служебная учётка — не учётка чтения и **не Domain Admins**. Делегируйте ей в «Делегировании управления»
только нужное:

| Операция | Где | Права |
|---|---|---|
| Добавить в группу | разрешённые группы (участник — из OU пользователей) | запись атрибута `member` |
| Разблокировать | OU пользователей | запись `lockoutTime` |
| Включить / отключить | OU пользователей | запись `userAccountControl` |
| Сбросить пароль | OU пользователей | «Сброс пароля», запись `pwdLastSet` |

Настройка — «Настройки → Каталог AD: запись» (разрешение `directory.manage`, по умолчанию у суперадминистратора):
DN или UPN учётки записи и её пароль (хранится зашифрованным ключом `PULT_SECRET_KEY`, в ответах не возвращается).
Пустое поле учётки выключает запись. Смена контроллеров, режима TLS или CA в «Каталоге AD» сбрасывает пароль учётки
записи — его вводят заново (иначе он ушёл бы на новый сервер).

## Области

- **OU, где можно менять учётки** — по одной на строку; вложенные OU тоже разрешены. Учётку вне этих OU Pult не тронет,
  даже если у учётки записи есть права.
- **Группы, куда можно добавлять** — полный DN, по одной на строку. Добавить можно только учётку из разрешённых OU.
- **Операция только по заявке** — без номера заявки операция не создаётся.

## Разрешения

| Код | Что даёт | По умолчанию |
|---|---|---|
| `directory.account.view` | видеть состояние учётки и операции | инженер, суперадминистратор |
| `directory.user.unlock` | разблокировать | суперадминистратор |
| `directory.user.enable` | включить и отключить | суперадминистратор |
| `directory.user.reset_password` | сбросить пароль | суперадминистратор |
| `directory.group.add_member` | добавить в группу | суперадминистратор |
| `directory.manage` | настройки записи | суперадминистратор |
| `helpdesk.access.resources` | каталог ресурсов и владельцев | суперадминистратор |

Инженерам права на запись выдаются в «Роли и права» осознанно.

## Как выполняется операция

1. Пользователь подтверждает операцию и указывает основание; сервер проверяет право, область, заявку и ключ
   идемпотентности и ставит фоновую задачу в той же транзакции.
2. Задача снова проверяет права запросившего (их могли отозвать), пишет учёткой записи, **читает результат**
   и сохраняет состояние «было/стало».
3. Итог пишется в ленту заявки (служебная заметка «Каталог AD») ровно один раз, в аудит — с основанием,
   контроллером и «было/стало». Повторная доставка задачи ничего не повторяет; прерванный сброс пароля
   не повторяется, а завершается ошибкой «проверьте учётку».
4. Нет связи с контроллерами — задача вернётся в очередь и повторится.

## Сброс пароля

Только по LDAPS (домен с `tls_mode = ldaps`). Временный пароль: 16 символов, все четыре класса, «сменить при входе».
Его видит один раз только запросивший («Показать временный пароль»); после показа он стирается, неполученный —
через сутки. В аудит и журналы пароль не попадает.

## Запросы доступа

Категория «Запрос доступа» (код `access`) просит выбрать ресурс. Исполнитель отправляет запрос владельцу ресурса
(колокольчик и письмо); владелец решает в «Согласованиях». Для ресурса-группы AD кнопка «Выполнить» добавляет
заявителя в группу через каталог; прочие ресурсы выдаются вручную. Сотрудник видит свои запросы в «Мои доступы».
