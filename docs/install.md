# Развёртывание Pult на сервере

Инструкция ведёт от пустой виртуальной машины до работающего портала. Обычно это занимает 30–60 минут.
Скрипты Windows и правка конфигов для базовой установки не нужны: всё делает пакет, остальное — мастер в
браузере. English: [install.en.md](install.en.md).

После установки — [настройка и работа](guide.md). Как всё устроено внутри — [architecture.md](architecture.md),
модель безопасности — [security.md](security.md).

## 1. Как это устроено

Pult — одна программа (`/opt/pult/bin/pult`) с встроенным веб-интерфейсом и база PostgreSQL. Программа
работает службой `pult`, сама отдаёт HTTPS на порту 443 и подключается к контроллерам домена только по
защищённому каналу (LDAPS или StartTLS). Сотрудники входят своим паролем Windows; служебная учётка портала
только читает каталог AD.

```
 браузеры сотрудников ──HTTPS 443──►  сервер Pult  ──LDAPS 636 / StartTLS 389──►  контроллеры домена
 агенты на ПК (по желанию) ─HTTPS 443─►  (служба pult  ──SMTP──►  почтовый сервер (по желанию)
                                         + PostgreSQL)
```

Пакет `.deb` при установке сам ставит PostgreSQL, создаёт базу, ключ шифрования и временный сертификат,
запускает службу. При обновлении — делает резервную копию и, если копия или миграция базы не удалась, возвращает
прежнюю версию.

## 2. Что подготовить заранее

### Сервер

| Что | Требование | Зачем |
|---|---|---|
| Система | Debian 13 или Ubuntu 24.04 и новее, x86-64 (amd64), systemd | Пакет собран и проверен для них |
| Ресурсы | 2 vCPU, от 2 ГБ памяти (лучше 4), от 20 ГБ диска | Портал и PostgreSQL на одном сервере; 14 ночных копий |
| Адрес | Постоянный IP (статический или резерв в DHCP) | На адрес указывает DNS-запись портала |
| Имя | Полное DNS-имя, например `pult.corp.example.test`, запись A во внутреннем DNS | По имени выдаётся сертификат и проверяется билет Kerberos |
| Время | Синхронизация NTP (лучше — с контроллерами домена) | Kerberos и коды из приложения не работают при расхождении больше 5 минут |
| Доступ к пакетам | Зеркало или локальный репозиторий дистрибутива | Пакет ставит из него PostgreSQL, если его нет |

Интернет серверу не нужен.

### Домен Active Directory

| Что | Где взять |
|---|---|
| Имя домена (`corp.example.test`) и NetBIOS-имя (`CORP`) | Свойства домена в «Пользователи и компьютеры AD» |
| Полные имена контроллеров (`dc1.corp.example.test`, `dc2.…`) | «Сайты и службы AD» или `nltest /dclist:CORP` |
| Контроллеры отвечают по LDAPS (TCP 636) | Обычно так, если в домене есть AD CS. Иначе — [раздел 15](#контроллеры-не-отвечают-по-ldaps) |
| Корневой сертификат CA, которым подписаны контроллеры (PEM) | Если CA внутренний: выгрузить из «Доверенные корневые центры сертификации» в Base64 |
| Служебная учётка для чтения каталога, например `svc-pult@corp.example.test` | Обычный пользователь домена без дополнительных прав, длинный пароль, срок без ограничения |

Служебная учётка только читает каталог. Изменения в AD (разблокировка, сброс пароля, группы) портал делает
другой учёткой, которую задают позже и по желанию — [directory.md](directory.md).

### Сеть

| Откуда | Куда | Порт | Зачем |
|---|---|---|---|
| ПК сотрудников | сервер Pult | TCP 443 | Портал |
| Сервер Pult | контроллеры домена | TCP 636 (LDAPS) или 389 (StartTLS) | Вход и синхронизация каталога |
| Сервер Pult | почтовый сервер | порт SMTP из настроек | Уведомления (по желанию) |
| Сервер Pult | сервер PostgreSQL | TCP 5432 | Только если база на другом сервере |
| Агенты на ПК | сервер Pult | TCP 443 | Удалённая поддержка (по желанию) |
| ПК инженеров | ПК сотрудников | TCP 445 и динамические RPC | Теневое подключение — [admin-guide.md](admin-guide.md) |

### Проверить сервер одной командой

Скрипт `install.sh` из релиза проверяет всё из таблиц выше, что видно с сервера, и объясняет, что
исправить. Ничего не меняет:

```bash
sudo sh install.sh --check --dc dc1.corp.example.test --dc dc2.corp.example.test
```

## 3. Где взять установщик

На странице **Releases** репозитория для каждой версии лежат:

| Файл | Что это |
|---|---|
| `pult_<версия>_amd64.deb` | Сервер: установка и обновление |
| `install.sh` | Проверка сервера и установка пакета (необязателен) |
| `pult-agent.msi` | Агент удалённой поддержки для ПК сотрудников (Windows) |
| `pult-helper.exe` | Помощник инженера для подключения к ПК (Windows) |
| `SHA256SUMS` | Контрольные суммы всех файлов |

Скачайте на сервер `.deb`, `install.sh` и `SHA256SUMS` в один каталог и проверьте суммы:

```bash
sha256sum -c --ignore-missing SHA256SUMS
```

Каждая строка должна закончиться `OK`. Собрать пакет из исходников — [CONTRIBUTING.md](../CONTRIBUTING.md),
раздел «Сборка установщиков».

## 4. Установка

Вариант со скриптом — сначала проверки, затем установка, в конце скрипт покажет адрес и код мастера:

```bash
sudo sh install.sh ./pult_<версия>_amd64.deb
```

Или напрямую, без проверок:

```bash
sudo apt install ./pult_<версия>_amd64.deb
```

Пакет сам:

- ставит PostgreSQL, если его нет (из репозитория дистрибутива);
- создаёт системного пользователя `pult`, базу и роль `pult` со случайным паролем;
- пишет настройки в `/etc/pult/pult.env` (права `root:pult 0640`: в файле пароль базы);
- создаёт ключ шифрования `/var/lib/pult/secret.key` и временный сертификат HTTPS;
- применяет миграции базы и запускает службу `pult` на порту 443.

Где что лежит:

| Путь | Что |
|---|---|
| `/opt/pult/bin/pult` | Программа (сервер и все команды) |
| `/etc/pult/pult.env` | Параметры службы ([раздел 13](#13-параметры-сервера)); пакет создаёт его один раз и больше не меняет |
| `/var/lib/pult/` | Данные: вложения, сертификат портала, `secret.key` |
| `/var/lib/pult/backups/` | Резервные копии |
| `pult.service` | Служба systemd: `systemctl status pult`, журнал — `journalctl -u pult` |

Проверка: `systemctl is-active pult` → `active`; `curl -k https://localhost/health` →
`{"status":"ok",…,"database":"up"}`.

## 5. Мастер первого запуска

Откройте `https://имя-сервера/`. Браузер предупредит о временном сертификате — это ожидаемо, настоящий
сертификат ставится в конце ([раздел 6](#6-сертификат-портала)). Язык мастера — в правом верхнем углу
(русский, English, 中文).

1. **Код установки.** Защищает мастер от постороннего, пока портал не настроен. Сервер пишет код в журнал:

   ```bash
   sudo journalctl -u pult | grep "SETUP CODE" | tail -n 1
   ```

   Код — слово сразу после `SETUP CODE:`. Он новый при каждом запуске службы, действует последний.

2. **Домен.** Имя домена, контроллеры (полные DNS-имена, в порядке приоритета), служебная учётка и её
   пароль, корневой сертификат CA, если контроллеры подписаны внутренним CA. Режим подключения — LDAPS
   (по умолчанию) или StartTLS.
3. **«Проверить подключение»** покажет состояние каждого контроллера и что исправить. Настройки
   домена сохраняются только после того, как контроллер примет пароль администратора на шаге 4.
4. **Вход администратора.** Войдите своей учётной записью домена — вы станете суперадминистратором.
   Сотрудники синхронизируются из AD сами.
5. **Организация.** Мастер продолжит: язык и название, логотип, модули, площадки, категории заявок, почта.
   Любой шаг можно пропустить и вернуться к нему в «Настройки → Система».

Что настроить дальше и зачем — [guide.md](guide.md), раздел «Первые шаги после установки».

## 6. Сертификат портала

Временный сертификат подходит только для проверки. Варианты:

- **Сертификат своего CA** (AD CS или любой внутренний): запрос на имя портала, назначение «Проверка
  подлинности сервера». ПК в домене доверяют ему сами. Если CA нет — [ad-setup.md](ad-setup.md),
  раздел «Сертификаты».
- **Публичный сертификат** (свой или wildcard организации) — если портал открыт из интернета.

Загрузка: **Настройки → Система → Сертификат портала** — сертификат с цепочкой и ключ в формате PEM.
Применяется сразу, без перезапуска.

Сертификат файлами вместо админки — в `/etc/pult/pult.env`:

```bash
PULT_TLS_CERT=/etc/pult/tls/pult.chain.crt
PULT_TLS_KEY=/etc/pult/tls/pult.key
# Вторая пара для другого имени портала (например, публичного): выбирается по имени, которое запросил клиент
PULT_TLS_EXTRA_CERT=/etc/pult/tls/public.chain.crt
PULT_TLS_EXTRA_KEY=/etc/pult/tls/public.key
```

Файлы ключей — `root:pult 0640`. После правки: `sudo systemctl restart pult`.

**HTTPS на обратном прокси** (nginx, HAProxy и т. п.):

```bash
PULT_AUTO_TLS=0                  # портал слушает обычный HTTP
PULT_LISTEN=127.0.0.1:8080       # адрес, на который прокси передаёт запросы
PULT_TRUSTED_PROXIES=192.0.2.5   # адреса прокси: только им портал верит в X-Forwarded-For
```

Адреса прокси указывать обязательно. Иначе все пользователи будут выглядеть одним адресом: лимит попыток
входа сработает на всех сразу, а вход из интернета нельзя будет отличить от входа из офиса.

## 7. Необязательные шаги

| Что | Зачем | Где |
|---|---|---|
| Вход через домен (Kerberos) | Вход без пароля с доменного ПК из сетей организации: настройте keytab, проверьте на странице «Состояние», затем включите в «Безопасность» | [ad-setup.md](ad-setup.md), разделы 3–4 |
| Доступ из интернета | Вход с телефонов без VPN, со вторым фактором по желанию | [go-live.md](go-live.md) |
| Агент удалённой поддержки | Список сеансов на ПК, подключение инженера из карточки | [admin-guide.md](admin-guide.md) |
| Изменения в AD из портала | Разблокировка, сброс пароля, группы, запросы доступа | [directory.md](directory.md) |
| Перенос из старого справочника | Сотрудники и телефоны из SQL Server | `pult import phonebook --help` |

Для проверки Kerberos keytab службы указывают в `/etc/pult/pult.env`: `KRB5_KTNAME=/etc/pult/pult-http.keytab`
(файл `root:pult 0640`), затем `sudo systemctl restart pult`.

## 8. Резервные копии и восстановление

Копии делаются каждую ночь в 02:30 и перед каждым обновлением, в `/var/lib/pult/backups/pult-<дата>/`;
хранятся последние 14 (число меняется в «Системе» → «Резервная копия», от 1 до 365). Каждая копия
проверяется: дамп читается `pg_restore --list`, испорченный в число готовых не попадает. В копии — `db.dump` (база), `files/` (вложения) и `tls/` (сертификат портала
**вместе с закрытым ключом** — храните копии как секрет). Результат последней копии виден в админке;
о неудачной суперадминистраторы получают уведомление.

Копию вручную:

```bash
sudo -u pult sh -c 'set -a; . /etc/pult/pult.env; set +a; cd /var/lib/pult; /opt/pult/bin/pult backup'
```

**Ключ шифрования `/var/lib/pult/secret.key` в копию не входит.** Кто получит копию, не расшифрует пароли
служебных учёток (AD, почта, АТС). Поэтому сразу после установки сохраните ключ отдельно от копий —
например, на носитель в сейфе или в менеджер паролей:

```bash
sudo install -m 0600 /var/lib/pult/secret.key /media/<носитель>/pult-secret.key
```

Копии забирайте на другой сервер или NAS (rsync, агент резервного копирования) — копия на том же диске не
спасёт при потере сервера.

Восстановление из копии `/var/lib/pult/backups/pult-<дата>`:

```bash
B=/var/lib/pult/backups/pult-<дата>
sudo systemctl stop pult
sudo -u postgres dropdb pult && sudo -u postgres createdb -O pult pult
sudo cat "$B/db.dump" | sudo -u postgres pg_restore -d pult    # каталог копий доступен только pult и root
for d in files tls; do
  sudo rm -rf "/var/lib/pult/$d"
  if sudo test -d "$B/$d"; then sudo cp -a "$B/$d" /var/lib/pult/ && sudo chown -R pult:pult "/var/lib/pult/$d"; fi
done
sudo install -o pult -g pult -m 0600 /media/<носитель>/pult-secret.key /var/lib/pult/secret.key
sudo systemctl start pult
```

На новый сервер: установите пакет той же или более новой версии, скопируйте каталог копии на сервер и
выполните те же команды. Служба при старте сама применит миграции, если пакет новее копии.

Если ключ потерян, служба создаст новый, а сохранённые пароли станут нечитаемыми. Пароль служебной учётки
AD задайте заново командой `pult setup ad` (те же параметры, что в мастере; без него не работает вход),
пароли почты, АТС и вебхуков — в админке.

## 9. Обновление

Новая версия ставится тем же способом:

```bash
sudo sh install.sh ./pult_<новая версия>_amd64.deb
# или
sudo apt install ./pult_<новая версия>_amd64.deb
```

Пакет останавливает службу, делает резервную копию, применяет миграции **одной транзакцией** и запускает
новую версию. Если копия не создалась или миграция не прошла, база остаётся как была, возвращается прежняя
версия программы и служба запускается на ней; `apt` сообщит об ошибке, подробности — `journalctl -u pult`.
Повторить обновление после устранения причины: `sudo dpkg --configure -a`.

Перед обновлением прочитайте раздел версии в `CHANGELOG.md`. Вернуться на прежнюю версию вручную можно,
только пока база не обновлена: `sudo apt install --allow-downgrades ./pult_<прежняя>_amd64.deb`; после
миграций — сначала восстановите копию ([раздел 8](#8-резервные-копии-и-восстановление)).

## 10. Удаление

```bash
sudo apt remove pult     # программа и служба; данные остаются
sudo apt purge pult      # то же; данные всё равно остаются — их удаляют вручную
```

Пакет никогда не удаляет данные сам: база `pult`, `/etc/pult` и `/var/lib/pult` (ключ и копии) нужны, чтобы
вернуть портал. Удалить всё окончательно — только если копии больше не нужны:

```bash
sudo -u postgres dropdb pult && sudo -u postgres dropuser pult
sudo rm -rf /etc/pult /var/lib/pult
```

## 11. Docker вместо пакета

Для серверов, где уже всё в контейнерах. Нужен Docker с Compose:

```bash
git clone <адрес репозитория> pult && cd pult
docker compose -f deploy/compose.yml up -d --build
```

Пароль базы, ключ шифрования и временный сертификат создаются сами; портал — на порту 443 (другой порт:
`PULT_HTTPS_PORT=8443` перед командой). Код мастера:

```bash
docker compose -f deploy/compose.yml logs pult | grep "SETUP CODE" | tail -n 1
```

Обновление: `git pull && docker compose -f deploy/compose.yml up -d --build` — миграции те же, одной
транзакцией. Резервная копия — тома `pult_pgdata`, `pult_data` и `pult_secrets` (в нём пароль базы: без него
восстановленная база не откроется). Копии при обновлении Docker не делает — сделайте её до `up -d --build`.
В `pult_data` лежит `secret.key`, храните его копию отдельно от копии базы.

При доступе из интернета Docker на части систем подменяет адрес клиента адресом своей сети (`172.x`) —
см. [go-live.md](go-live.md), абзац «Docker».

## 12. База на другом сервере

Перед установкой поставьте вместо PostgreSQL только клиент: `sudo apt install postgresql-client`. На сервере
базы (PostgreSQL 15 или новее) администратор создаёт роль и базу:

```sql
CREATE ROLE pult LOGIN PASSWORD '…';
CREATE DATABASE pult OWNER pult;
\c pult
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;
```

После установки пакета впишите адрес в `/etc/pult/pult.env` и перезапустите службу:

```bash
PULT_DATABASE_URL=postgres://pult:ПАРОЛЬ@db.corp.example.test:5432/pult
```

```bash
sudo systemctl restart pult
```

Пароль можно держать отдельным файлом: оставьте в `PULT_DATABASE_URL` адрес без пароля
(`postgres://pult@db.corp.example.test:5432/pult`) и добавьте `PULT_DATABASE_PASSWORD_FILE=/etc/pult/db-password`
(файл `root:pult 0640`).

Несколько копий сервера, кластер PostgreSQL и оценка нагрузки для крупных установок — в
[scale.md](scale.md).

## 13. Параметры сервера

Все параметры — переменные в `/etc/pult/pult.env` (после правки — `sudo systemctl restart pult`). Их же
можно задать файлом `/var/lib/pult/pult.toml` (другой путь — `PULT_CONFIG`); переменные окружения важнее
файла, неизвестный ключ в файле — ошибка запуска. Образец `deploy/pult.example.toml` есть в репозитории,
в пакет он не входит.

| Переменная | Значение по умолчанию | Что задаёт |
|---|---|---|
| `PULT_DATABASE_URL` | пишет пакет | Адрес базы PostgreSQL |
| `PULT_DATABASE_PASSWORD_FILE` | — | Пароль базы из файла; подставляется в `PULT_DATABASE_URL`, который должен быть задан |
| `PULT_LISTEN` | `0.0.0.0:443` (пакет) | Адрес и порт службы |
| `PULT_AUTO_TLS` | `1` (пакет) | Сертификат из админки; `0` — без HTTPS (за прокси) |
| `PULT_TLS_CERT`, `PULT_TLS_KEY` | — | Сертификат и ключ файлами |
| `PULT_TLS_EXTRA_CERT`, `PULT_TLS_EXTRA_KEY` | — | Вторая пара для другого имени портала |
| `PULT_TRUSTED_PROXIES` | — | Адреса или сети обратных прокси через запятую |
| `PULT_DATA_DIR` | `/var/lib/pult` (пакет) | Вложения, сертификат, ключ |
| `PULT_BACKUP_DIR` | `<PULT_DATA_DIR>/backups` | Каталог резервных копий |
| `PULT_SECRET_KEY` | файл `secret.key` | Ключ шифрования строкой (не короче 32 символов) |
| `PULT_INITIAL_SUPERADMIN` | — | Логин, который станет суперадминистратором при первом входе |
| `PULT_METRICS_TOKEN` | — | Токен для опроса `/metrics` (Prometheus) с другого сервера; без него `/metrics` отвечает только локально |
| `PULT_LOG_FORMAT` | `json` (пакет) | Формат журнала: `json` или `text` |
| `KRB5_KTNAME` | — | Keytab для входа через домен (Kerberos) |

Шаблон со всеми переменными — `.env.example` в корне репозитория.

## 14. Команды pult

Команды запускаются с параметрами службы:

```bash
sudo -u pult sh -c 'set -a; . /etc/pult/pult.env; set +a; cd /var/lib/pult; /opt/pult/bin/pult <команда>'
```

| Команда | Что делает |
|---|---|
| `pult version` | Версия |
| `pult check db` | Подключение к базе и состояние миграций |
| `pult check ad` | Служебная учётка и синхронизация каталога. Подключение берёт из секции `[ad]` файла `pult.toml`, а не из базы: для домена из мастера нужен этот файл (пароль — `PULT_AD_BIND_PASSWORD`) |
| `pult check ad --login ivanov` | Вход этой учётки (пароль спросит без отображения) |
| `pult backup` | Резервная копия сейчас |
| `pult migrate` | Применить миграции (служба делает это сама при старте) |
| `pult setup ad …` | Задать подключение к домену без мастера (`--help` — параметры) |
| `pult import phonebook …` | Перенос из старого справочника на SQL Server (`--help`) |
| `pult serve` | Запуск сервера (это делает служба) |

## 15. Неполадки

| Признак | Причина и что сделать |
|---|---|
| `apt` не может поставить `postgresql` | Нет доступа к зеркалу: `sudo apt update`, подключите зеркало или локальный репозиторий; либо база на другом сервере ([раздел 12](#12-база-на-другом-сервере)) |
| «база не настроена — служба НЕ запущена» | PostgreSQL на сервере не найден: впишите `PULT_DATABASE_URL` и `sudo systemctl restart pult` |
| Служба не стартует, порт 443 занят | Другая программа слушает 443 (`sudo ss -ltnp 'sport = :443'`): остановите её или задайте `PULT_LISTEN` |
| Страница не открывается с ПК | Брандмауэр сервера или сети: откройте TCP 443 с сетей сотрудников; проверьте DNS-запись |
| Мастер не принимает код | Код меняется при каждом запуске службы — возьмите последний из журнала |
| «Контроллер оборвал TLS-соединение» | У контроллера нет сертификата для LDAPS — ниже |
| Ошибка проверки сертификата контроллера | Загрузите в мастере корневой сертификат CA (PEM); имя контроллера должно совпадать с SAN сертификата |
| Вход «неверный логин или пароль» при верном пароле | Учётка отключена, пароль истёк или требуется смена пароля: проверьте учётку в AD и «Настройки → Active Directory: синхронизация → Проверить подключение»; точную причину покажет `pult check ad --login <логин>` (нужен `pult.toml` с `[ad]`) |
| «Состояние» не распознаёт учётку по Kerberos | Портал открыт по IP, а не по имени; нет keytab или SPN; сайт не в зоне «Местная интрасеть» — [ad-setup.md](ad-setup.md) |
| Обновление завершилось ошибкой | Ошибка на копии или миграции — база не изменена, прежняя версия работает. Служба не запустилась после миграций — база уже новая, прежняя версия с ней не запустится: причина в `journalctl -u pult`, повтор — `sudo dpkg --configure -a`, при необходимости восстановите копию ([раздел 8](#8-резервные-копии-и-восстановление)) |

### Контроллеры не отвечают по LDAPS

Портал подключается к AD только по защищённому соединению. Если мастер пишет «Контроллер оборвал
TLS-соединение», у контроллера нет сертификата:

- **В домене есть AD CS** — контроллеры обычно получают сертификат сами (шаблон «Контроллер домена» или
  «Проверка подлинности Kerberos»); перезапуск контроллера или `certutil -pulse` ускорит выпуск.
- **AD CS нет** — установите его или выпустите сертификат своим способом. Требования: в хранилище
  компьютера на контроллере, полное имя контроллера в SAN, назначение «Проверка подлинности сервера».
  Готовые инструменты для варианта без AD CS — [ad-setup.md](ad-setup.md).
- Если закрыт только порт 636, а сертификат у контроллера есть, выберите в мастере StartTLS (порт 389):
  `sudo sh install.sh --check --dc <контроллер>` покажет, какой вариант работает.

Журнал службы — первое место для поиска причины: `sudo journalctl -u pult -n 200`.
