# ADR-0003 — Технологический стек

- **Статус:** принято.
- **Дата:** 2026-11-02.
- **Уточняет:** [ADR-0001](ADR-0001-rust-core.md) в части фреймворка, интерфейса и входа.

## Контекст

Требования, влияющие на стек:

- установка «один исполняемый файл + PostgreSQL», без обязательных сторонних сервисов;
- вход по логину и паролю AD, данные сотрудников синхронизируются из AD;
- в справочнике бывают сотрудники **без учётной записи AD** (нет своего ПК), поэтому «человек в
  справочнике» и «учётная запись AD» — разные сущности;
- агент на ПК и утилита инженера — небольшие исполняемые файлы без зависимостей.

## Решение

| Область | Решение |
|---|---|
| Ядро | Rust stable, Edition 2024, Tokio, Axum + tower / tower-http. Модульный монолит, один исполняемый файл; веб-интерфейс встроен в него |
| База данных | PostgreSQL 15+, SQLx с проверкой запросов и миграциями только вперёд |
| Фоновые задачи | Очередь в той же PostgreSQL (`FOR UPDATE SKIP LOCKED`) — [ADR-0004](ADR-0004-job-queue.md). Без Redis и брокеров |
| Интерфейс | React + TypeScript (Vite), TanStack Router/Query, Tailwind, i18next |
| API | REST/JSON; схема OpenAPI из кода (`utoipa`), клиент TypeScript генерируется из схемы и сверяется в CI |
| Вход | LDAP bind к AD только по LDAPS или StartTLS. Сессия — httpOnly Secure cookie, хранится в PostgreSQL; защита от CSRF; лимиты попыток. Своих паролей у сотрудников нет. TOTP — по желанию |
| Kerberos | SPNEGO через MIT GSSAPI по keytab, NTLM отклоняется. В 0.1.0 — проверка билета; вход по нему — следующий шаг |
| TLS | Встроенный в сервер (rustls), HSTS; обратный прокси — допустимый вариант |
| Синхронизация с AD | Полная постранично и инкрементальная по `uSNChanged`; служебная учётка только на чтение; перебор контроллеров; отключённые учётки архивируются; атрибуты из AD в портале не редактируются |
| Почта | Отправка через SMTP (`lettre`); приёма писем нет: заявки создаются в портале |
| Телефония | Адаптер «звонок по клику» с интерфейсом провайдера |
| Агент на ПК | Служба Windows на Rust (WTS API): сообщает текущие сеансы. Только исходящие HTTPS-соединения |
| Утилита инженера | Rust, Windows: обработчик ссылок `pult://` из портала, запускает `mstsc /shadow` |
| Журналы и метрики | `tracing` (текст или JSON), `/metrics` в формате Prometheus, `/health` |
| Конфигурация | TOML и переменные окружения для инфраструктуры; прикладные настройки — в базе, правятся в админке |
| Поставка | Пакет `.deb` с systemd, образ контейнера и Docker Compose; MSI для агента |

## Рассмотренные альтернативы

1. **Actix Web** — равноценен; выбран Axum, чтобы ядро и модули использовали одну экосистему tower.
2. **Leptos или htmx + Askama вместо React** — один язык, но беднее компоненты для сложного интерфейса.
3. **Обязательный внешний IdP (Keycloak)** — готовые SSO и MFA, но установка перестаёт быть «бинарник +
   PostgreSQL».

## Последствия

- Пароли AD проходят через сервер портала, поэтому TLS до портала и до AD обязателен, а пароли нигде не
  сохраняются и не пишутся в журналы.
- Проверка Kerberos собирается только под Linux (нужны `libkrb5-dev` и `libclang`); на других системах этот
  маршрут отвечает 501.
- Минимальная версия Rust — 1.88: её требуют исправленные версии TLS-библиотек; `cargo deny` в CI — без
  исключений.

## Критерии пересмотра

Замена отдельной библиотеки (очередь задач, LDAP, Kerberos) — новым ADR с измеримой причиной.
