# ADR-0005 — Расширения: внешние сервисы по манифесту

- **Статус:** принято.
- **Дата:** 2026-11-20.

## Контекст

Организациям нужны сторонние модули: свои отчёты, связь с учётными системами, обработка событий заявок
(D-178). Ставить их хотят из каталога и из локальных пакетов (D-179), любые совместимые, под свою
ответственность (D-180). В портале уже есть REST API с токенами только на чтение и подписанные вебхуки
(раздел 3.7 руководства).

Рассматривались три модели:

1. **Внешние сервисы по API и вебхукам.** Расширение работает отдельным процессом (на своём сервере или в
   контейнере) и общается с порталом только по HTTP.
2. **WASM-плагины в песочнице** (`wasmtime`) с явными разрешениями на вызовы хоста.
3. **Нативные динамические библиотеки** (`.so`, `.dll`).

## Решение

Модель 1. Расширение описывается манифестом `pult-extension.json`:

```json
{
  "manifest_version": 1,
  "id": "com.example.sla",
  "name": "SLA-отчёт",
  "version": "1.0.0",
  "publisher": "Example",
  "description": "Отчёт по срокам для руководителей",
  "homepage": "https://ext.example.local/",
  "permissions": ["helpdesk.reports", "helpdesk.ticket.work"],
  "webhook": { "url": "https://ext.example.local/hook", "events": ["created", "status"] },
  "links": [{ "title": "Отчёт SLA", "url": "https://ext.example.local/sla", "permission": "helpdesk.reports" }]
}
```

При установке («Настройки» → «Расширения», только суперадминистратор) портал:

- проверяет манифест: известная версия формата, идентификатор, адреса только https (вебхук — http только
  на localhost), права — из списка прав портала; вебхук с событиями — только у расширения, которое просит
  право `helpdesk.ticket.work`: в событиях есть номера, темы и статусы заявок;
- показывает, какие права просит расширение, куда пойдут события заявок и какие ссылки появятся в меню;
- выпускает **токен API** с этими правами. Токен, как и любой другой, только читает (GET) и не даёт прав
  больше, чем перечислено;
- создаёт **вебхук** формата `pult` (JSON с подписью HMAC-SHA256) со случайным секретом;
- показывает токен и секрет **один раз** — их вносят в настройки расширения;
- добавляет **ссылки** в меню: каждому видны только те, на которые у него есть право; открываются в новой
  вкладке.

Выключение отзывает токен, выключает вебхук и прячет ссылки. Включение выпускает новый токен и секрет.
Удаление отзывает токен и удаляет вебхук. Установка, включение, выключение, удаление и смена каталога
записываются в аудит.

**Источники:** файл манифеста (локальный пакет), адрес манифеста или каталог. Каталог — адрес JSON-массива
манифестов, который задаёт суперадминистратор. Его можно держать на внутреннем сервере организации.
Негодные манифесты каталога пропускаются. Скачивание — по https, без перенаправлений, не больше 1 МБ,
за 15 секунд.

**Обновление:** удалить и установить новую версию. Права и вебхук выдаются заново и снова показываются
суперадминистратору: молча расширить права при обновлении нельзя.

## Почему не WASM и не динамические библиотеки

- Нативные библиотеки в Rust не имеют стабильного ABI и не изолированы. Ошибка или вредоносный код
  расширения работали бы с правами процесса портала, то есть с доступом к базе и ключу шифрования.
- WASM даёт изоляцию, но требует своего API хоста, версионирования этого API, лимитов памяти и времени и
  новой зависимости (`wasmtime`) в ядре. Расширения, которые просят организации, — отчёты, синхронизация и
  уведомления. Им хватает HTTP, и пишутся они на любом языке.
- Внешний сервис не может прочитать того, на что у него нет прав. Его можно остановить, отозвав токен, не
  трогая портал. Обновление портала его не ломает, пока сохраняется API.

## Последствия

- Расширение не встраивает свои страницы в интерфейс портала: только ссылки. Встраивание (iframe) не
  делается: оно потребовало бы ослабить CSP `frame-ancestors`.
- Запись через API расширениям недоступна, как и любым токенам. Действия, меняющие данные, расширение
  предлагает человеку: например, ссылкой на заявку.
- Модель WASM можно добавить позже как второй вид расширений, не меняя формат манифеста: поле
  `manifest_version` для этого и нужно.
