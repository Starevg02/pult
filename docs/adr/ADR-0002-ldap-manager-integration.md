# ADR-0002 — Изменения в AD — модуль портала, а не отдельное приложение

- **Статус:** принято.
- **Дата:** 2026-10-30.

## Контекст

IT-службе нужны операции с каталогом AD (разблокировка, сброс пароля, состав групп) и запросы на доступ с
согласованием. Отдельный «менеджер LDAP» дублировал бы вход, роли, интерфейс, аудит и поддержку, и
операции не были бы связаны с заявками.

## Решение

Изменения в AD — модуль портала (`pult-directory`) с общими сессией, правами, аудитом и уведомлениями.
Внутри строго разделены:

- **чтение каталога** — служебная учётка только на чтение, синхронизация в базу портала;
- **изменения** — отдельная учётка записи с делегированными правами только на нужные OU и группы;
- **исполнение** — фоновая задача с ключом идемпотентности, проверкой результата чтением после записи и
  записью в аудит.

По умолчанию — только чтение. Изменения разрешаются типизированными операциями по областям (OU, группы,
атрибуты), а не произвольным редактированием объектов. Подробности — [directory.md](../directory.md).

## Рассмотренные альтернативы

1. **Отдельное приложение с собственным входом** — больше интерфейсов, механизмов авторизации и журналов,
   нет связи с заявками.
2. **Всё вручную в RSAT** — минимальный риск, но нет сквозной истории и автоматизации. Для
   привилегированных действий RSAT остаётся основным инструментом.

## Последствия

- Операции связаны с заявками, согласованиями и аудитом в одном месте.
- Ошибка прав здесь опаснее, чем в обычной системе заявок: права выдаются по областям, учётка записи — вне
  привилегированных групп, каждая операция проверяется чтением.
- AD-специфичные операции не обещаются для других LDAP-серверов.
