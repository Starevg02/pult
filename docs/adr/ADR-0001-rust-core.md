# ADR-0001 — Rust как основной язык

- **Статус:** принято.
- **Дата:** 2026-10-30.

## Контекст

Портал IT-поддержки держит пароли сотрудников в памяти на время входа, служебные учётки AD и доступ к ПК
пользователей. Его ставят на один сервер организации и обновляют редко, без отдельной команды разработки
рядом. Нужны: надёжность при годах работы без присмотра, малое потребление ресурсов, поставка одним файлом
без среды выполнения, один язык для сервера, агента на ПК и утилиты инженера.

## Решение

Сервер, агент для Windows и утилита инженера пишутся на Rust (stable, Edition 2024). HTTP — Axum на Tokio и
Tower, база — PostgreSQL через SQLx. Веб-интерфейс — React и TypeScript: Rust на сервере не требует Rust в
браузере.

## Рассмотренные альтернативы

1. **Python / FastAPI** — быстрый старт, но нужна среда выполнения на сервере и на ПК; ошибки типов видны
   только при работе.
2. **Go** — зрелые библиотеки для AD и Kerberos, быстрая разработка; меньше гарантий компилятора для
   состояний и ошибок, которые здесь критичны.
3. **Rust + Leptos/WASM для интерфейса** — один язык, но беднее набор компонентов для сложного интерфейса.
4. **Микросервисы** — преждевременное усложнение для одного сервера.

## Последствия

- Один язык для серверной логики, фоновых задач, агента и утилиты; типы и ошибки проверяет компилятор.
- Разработка медленнее, чем на Go или Python; модели состояний и ошибок продумываются заранее.
- Поставка — один исполняемый файл со встроенным интерфейсом и миграциями.

## Критерии пересмотра

Замена HTTP-фреймворка или интерфейса — только новым ADR с измеримыми причинами.
