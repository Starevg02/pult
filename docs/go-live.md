# Запуск в организации: доступ из интернета

Чек-лист для выхода портала «в прод» с доступом с телефонов без VPN. Всё, что ниже, делает администратор
организации: портал сам не меняет DNS, роутер и политики домена. Имя портала ниже — `pult.example.com`,
внутренний адрес сервера — `10.0.0.10`; подставьте свои.

## Как защищён вход снаружи

- Адрес клиента вне **сетей организации** (Настройки → Безопасность, по умолчанию частные сети
  10/8, 172.16/12, 192.168/16) — вход «из интернета». По умолчанию это вход по паролю, как в офисе.
- **Код из приложения-аутентификатора** (TOTP, 6 цифр) — по желанию: кто подключил его в профиле, у того
  снаружи спросят и код. Роли, которым код обязателен, отмечаются в Настройки → Безопасность (по умолчанию —
  никому); без подключённого кода такая роль снаружи не войдёт. Рекомендуем отметить инженеров и
  суперадминистраторов: через их учётки доступны все заявки, операции в AD и подключение к ПК.
- У кого код подключён, он проверяется **до** пароля: подбор пароля из интернета не доходит до домена.
- Неудачи снаружи считаются отдельно: перебор из интернета не закрывает вход сотрудникам в офисе.
  Снаружи — неудачи на логин за окно (настройка) и не больше 20 за сутки (дальше вход снаружи закрыт до
  следующих суток). Без кода попытки снаружи доходят до AD: держите лимит на логин **ниже** порога блокировки
  домена, иначе из интернета можно заблокировать учётку сотрудника.
- Второй фактор подключают и отключают **только из сети организации** (Профиль → Вход из интернета).
  Потерян телефон — суперадминистратор нажимает «Сбросить 2FA» (Админка → Пользователи): все сеансы
  пользователя закрываются.

## 1. Сеть

1. **Публичный DNS**: запись `A pult.example.com` → внешний адрес роутера.
2. **Внутренний DNS**: та же запись → `10.0.0.10` (зона-заглушка или запись в зоне домена), чтобы ПК в офисе
   шли на сервер напрямую.
3. **Роутер**: проброс TCP 443 → `10.0.0.10:443` **без подмены адреса источника** (без SNAT/маскарадинга
   для этого правила). Иначе портал видит у всех клиентов внутренний адрес роутера, считает их «своими»
   и не спрашивает код. Это главное условие безопасности.
4. **Брандмауэр сервера**: открыть 443 для всех адресов (до запуска он мог быть открыт только для сети
   организации).
5. Если перед порталом стоит обратный прокси — укажите его адрес в `PULT_TRUSTED_PROXIES`, а прокси пусть
   передаёт адрес клиента в `X-Forwarded-For`. Без этого
   все запросы через прокси считаются пришедшими из интернета (код спросят и в офисе).

## 2. Сертификат

Нужен сертификат публичного центра для `pult.example.com` (или wildcard организации). Загрузка: Настройки →
Система → Сертификат портала (PEM, сертификат с цепочкой и ключ). Срок Let's Encrypt — 90 дней: продление
вручную, поставьте напоминание.

Если сертификат задан файлами (`PULT_TLS_CERT`, `PULT_TLS_KEY`) и на нём держится внутреннее имя (свой CA,
Kerberos, агенты), его не заменяйте: внешний сертификат добавьте второй парой — `PULT_TLS_EXTRA_CERT` и
`PULT_TLS_EXTRA_KEY`, затем `systemctl restart pult`. Клиент, запросивший имя из внешнего сертификата, получит
его; запросы по внутреннему имени и по IP — прежний.

## 3. Настройки портала

1. Настройки → Безопасность → **Сети организации**: перечислите свои сети (лучше точные, например
   `10.0.0.0/16`, а не все частные). Сеть шире /8 портал не примет.
2. Там же — лимит неудач на логин **строже** порога блокировки в домене: если домен блокирует после 5 ошибок
   за 15 минут, поставьте окно 15 минут и 4 неудачи.
3. Настройки заявок → адрес портала (ссылки в письмах): `https://pult.example.com`.
4. Агенты на ПК: `PortalUrl` в политике (GPO) — новое имя.
5. Kerberos с новым именем (если настроен) — SPN `HTTP/pult.example.com` на учётке портала и новый keytab
   (делает администратор домена, см. `docs/ad-setup.md`).

## 4. Люди

1. Не меньше двух суперадминистраторов; оба подключают второй фактор из офиса.
2. Сотрудникам, кому нужен доступ с телефона: Профиль → **Вход из интернета** → «Подключить» → ключ в
   приложение (Яндекс Ключ, Google Authenticator, Microsoft Authenticator, FreeOTP) → код.

## 5. Сохранность

1. Ключ шифрования `/var/lib/pult/secret.key` (или `PULT_SECRET_KEY`) — копия **отдельно** от резервных
   копий (сейф, менеджер паролей). Без него пароли служебных учёток в копии не расшифровать.
2. Резервные копии `/var/lib/pult/backups` — забирать на другой сервер или NAS ежедневно.
3. Временные права, выданные на время внедрения (sudo без пароля, сервисные доступы), — отозвать.

## 6. Проверка перед открытием

С телефона **через мобильный интернет** (не Wi-Fi офиса), учёткой, у которой код подключён:

- [ ] `https://pult.example.com` открывается без предупреждения о сертификате;
- [ ] после пароля портал просит «Код из приложения» — значит, он видит внешний адрес (если пускает без кода,
      роутер или Docker подменяет адрес источника: закройте проброс и исправьте);
- [ ] с неверным кодом вход не проходит, с верным — проходит;
- [ ] в Админка → Аудит у входа отмечено `external: true`;
- [ ] в профиле на телефоне «Подключить» недоступно (только из сети организации).

Из офиса: вход без кода как раньше; в профиле «Подключить» доступно.

**Docker.** Пробрасывая порт в контейнер, Docker на части систем подменяет адрес клиента адресом своего моста
(`172.x`) — из «частных сетей» по умолчанию. Тогда все клиенты выглядят «своими». Перечислите в «Сетях
организации» только свои сети (без `172.16.0.0/12`, если её нет в офисе) и пройдите проверку выше.

## Откат

Закрыть проброс 443 на роутере — портал снова доступен только из сети организации; данные и настройки
не меняются.
